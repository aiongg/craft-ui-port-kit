## Writer notes

1. Rows: `rows(app) -> Vec<ChannelRow<Row>>` follows `show`'s order today (:330-342): Composite unless Multichannel, colour rows when the mode has more than one, the active layer's mask row, alphas (spot ones as `ChannelKind::Spot`), Quick Mask. ## Decisions

1. `ChannelThumbs::revision`: `pixel_revision` for Composite and Color keys; for Alpha, QuickMask and LayerMask keys the `surface_fingerprint` of the channel or mask surface plus the layer id, so channel-list changes with empty damage refresh them.
2. Delete Channel on the layer-mask row is greyed by panels-w6's `applies_to` (its decision 4); `command_states` is `channels::states(&rows(app))` with no patch of its own.
3. Swatches file requests and display colours: Read the signatures you need (top-w28's `Files` service rows in the contract parts, grep `PresetFileRequest`, `Files`; `CmykConverter` and `.cmyk(` in the framework tree's crates/color) and code against them; the production path builds the converter from the working CMYK profile the way the contract or the color crate's docs say.
4. `SwatchesFileOutput` is `{edit, report, status}` as pn.C27 says (panels-w6 removes `changed`); code against the contract.
5. Mask-row Delete opens the prompt directly through `alerts::prompt_tagged::<MaskTrash>`; the old `(cmd, params)` pair goes for that case and `drop_action`'s mask-row return changes with it. One path.
6. `pixel_revision` moves at the one place every applied result passes through (where a step's damage is recorded), so synchronous commands in `Session::dispatch` and job results in `apply_job` (filters, strokes) both bump it; it moves only when the damage is not empty (`None` counts as everything).
