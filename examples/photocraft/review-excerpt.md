## dialogs-w19: verdict **needs fixes**

Agent-written (Sonnet, 86 turns, finished). Hosted-dialog glue in dialogs.rs; dialog_alt_reset.rs, edit_history.rs and label_column_tests.rs deleted; docs rewritten. All four new trials and both rewrites in the Tests table exist.

1. **dialogs.rs:146-157 (combined): non-exhaustive match on `DialogResult` (E0004, real).** `DialogResult` is `#[non_exhaustive]` (ui-panels dialog/host.rs:19). Both matches in `params::take` need a `_` arm (treat as Cancel). Writer error, a grep check catches it (a known writer-error class). Medium.
2. **dialogs.rs:130, :137, :165, :472 (combined): `Framework::captured` does not exist (E0559, real).** The PLAN at :130 assumed hub-w1 adds `captured: BTreeMap<String, Value>`; area/pcb2's app/framework.rs has `host()` and `move_memories` but no `captured`. Batch 1 owes nothing more, so the w19 fix adds the field to app/framework.rs itself (one line plus `Default`). Cross-tree bookkeeping. High (the crate does not compile).
3. **dialogs.rs:66-68 (combined): the Fill, Stroke and Smart Filter rows do not fit `ParamFamily` (E0308, real).** `fill_ui::check`, `stroke_ui::check`, `smart_filter_dialog::check` take `(&PhotocraftApp, &ParamResult, &Value)` and their `run` takes a fourth `Value`: they expect the captured value as an argument, while the row type reads it with `captured(app, key)`. The cx.P8 row and w19's type say `check(&mut App, &ParamResult)` and `run(app, ctx, ParamResult)`. The family modules move (smart_filter_dialog is dialogs-w27's; fill_ui and stroke_ui belong to later dialogs sets): they call `dialogs::captured(app, &result.key)` inside. Cross-set disagreement; the sheet is right. High.
4. **dialogs.rs:85, :94 (combined): `filter_dialog::run_command` is not a family `run` (E0308, real).** dialogs-w24 wrote `run_command(app, ctx, command: &str, ParamResult) -> Result<Value, String>`. The view-form row and the generic filter row need `fn(&mut App, &Context, ParamResult)`. Fix in w24: a `run(app, ctx, result)` that reads the command from `result.key` and reports an `Err` through the notice path; w19's rows name it. Cross-set. High.
5. **dialogs.rs:490, :512 (combined): two opener calls do not type-check (E0308, real).** `guide_layout_ui::open` returns `Option<DialogId>` (guide_layout_ui.rs:223); the dialogs shared-notes file gives every opener `open_command_dialog` routes to `Result<DialogId, String>`, so that opener moves (dialogs-w55). At :512, `adjust_dialog::open` returns `Result<DialogId, String>` (adjust_dialog.rs:293, dialogs-w32 followed the rule), and w19 matches it as `Option` under a PLAN. w19 moves: `if adjust_dialog::has_dialog(command) { return adjust_dialog::open(app, command); }`, and the PLAN at :510 goes. The batch-1 caller panels/actions/runner.rs:196 calls `filter_dialog::open(..).ok_or_else(..)` on what is a `Result` (filter_dialog.rs:501): the batch-1 caller moves (drop the `ok_or_else`). Medium.
5a. **`params::open_param_unsaved` does not exist.** dialogs-w24's decisions request "`open_param` with no remember key for spec dialogs and smart edits" from w19, and filter_dialog.rs:527 and :542 call `crate::dialogs::params::open_param_unsaved`. w19 did not write it. The gate shows no error at filter_dialog.rs for it, so the gate missed this one. Cross-set request not applied. High.
6. **dialogs.rs:598 and :600 (combined): `pub(crate) mod canvas_input;` twice (E0428; rust-analyzer does not show it).** w19 and dialogs-w32 both add the line; the combine kept both. dialogs-w32 writes canvas_input.rs, and the writer of a file writes its `mod` line (a plan rule), so w19's line (:598, after `brush_preset_dialog`) goes. Cross-tree bookkeeping. High.
7. **dialogs.rs:529: two of the four don't-show-again constants are unreachable.** `delete_layer_prompt::PREF` is private (`delete_layer_prompt.rs:8`, dialogs-w21 did not make it `pub(crate)` as the PLAN at :526 asks), `crate::analysis::DELETE_NOTE_PREF` does not exist (the constant is `analysis::note_alerts::DELETE_NOTE_PREF`; `analysis/mod.rs:21` re-exports nothing), and `crate::retouch_ui::CAM_NO_PIXELS_PREF` is private (`retouch_ui.rs:547`). rust-analyzer misses privacy (E0603). Fix: w21 makes `PREF` `pub(crate)`; w19 names `analysis::note_alerts::DELETE_NOTE_PREF`; the retouch constant's owner makes it `pub(crate)`. Drop the PLAN. Medium.
8. **dialogs/tests.rs:94-121 and :213-246: two harness trials run on a second context (R58).** Both build `Harness::builder()..build_ui_state(..)` without `.with_context(app.ctx().clone())` and call `PhotocraftApp::setup_context(&h.ctx, ..)`. `testing::confirm` (dialogs.rs, `mod testing`) runs on `app.ctx()`, so the colour-row trial confirms the picker on a context the harness never runs, and the pick list in temp memory lives on the other context. w19's decisions.md has the R58 line, so this is a writer error. Fix: `Harness::builder().with_context(app.ctx().clone())`, drop the `setup_context` call (R71: `new` installs). High (both trials fail).
9. **dialogs/tests.rs:24: `FilterPreviewKey::dialog` is `u64` (E0308).** The trial passes a `DialogId`, as it should. The key's field is dialogs-w24's (filter_dialog.rs); it should carry a `DialogId`, not a raw number. Cross-set. Low.
10. **dialogs.rs:146-149 (combined), low: a cancelled dialog's id is computed from its key.** `DialogResult::Cancel => dialog_id(key)` assumes the hosted dialog's id is `dialog_id(key)`. The host stores each result's id (`StoredResult::id`, host.rs:308). Use the framework's own fact: `take_keyed` returns the id beside the key (framework, one line), and the glue reads it. 11. **dialogs.rs:8, :61 PLAN markers (low).** `craft::settings` resolves on the combined tree (no gate error), so :8 is settled. :61's guess note is settled by the rows on the combined tree; replace with nothing.
